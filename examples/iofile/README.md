# iofile — файл на диске RT-11

Создаёт `GREET.TXT`, пишет в него строку, закрывает, открывает заново, читает
обратно в буфер и печатает прочитанное в консоль. Весь ввод-вывод — через
`open`/`read`/`write`/`close`, то есть через те самые системные вызовы, что
порт newlib (`libc/sys/rt11/`) реализует поверх программных запросов RT-11.

## Сборка и запуск

```bash
make                            # iofile.sav и iofile.dsk
make iofile.elf
../../gcc/dejagnu/uknc-run iofile.sav
```

Файл создаётся на том диске, с которого программа запущена. `uknc-run`
работает на временной копии образа и удаляет её за собой, так что `GREET.TXT`
останется только после запуска с `iofile.dsk` в эмуляторе — там его видно и
по `DIR` в RT-11, и снаружи:

```bash
../../debugger/bin/ukncbtldebug --disk1 iofile.dsk \
    --rom ../../rom/uknc_rom_autoboot.bin --boot --screen
rt11dsk l iofile.dsk
```

## Что в нём смотреть

- Имя файла — `GREET.TXT`: шесть символов и три, как требует RT-11.
- Перевод строки в сообщении записан как `\r\n`: в RT-11 консоль и файлы
  байты не преобразуют, перевод строки делает сама программа. На чтении порт
  newlib переводит CR в `\n` сам (см. раздел про newlib в README проекта).
- Файловый ввод-вывод здесь намеренно без `stdio`: смешивать буферизованный
  `printf` с настоящими файловыми операциями в одной программе на этом
  тулчейне пока нельзя — известная, неисправленная ошибка кодогенерации
  pdp11-бэкенда gcc. Про ограничения файлового ввода-вывода (размер, `seek`,
  перезапись) — в разделе про newlib.
