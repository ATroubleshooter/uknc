# sin — синусоида, посчитанная библиотекой

Бегущая по экрану 320×288 синусоида, до нажатия любой клавиши. Кривую считает
`sinf()` из стандартной библиотеки, а не таблица, набитая руками, — в этом и
смысл примера.

## Сборка и запуск

```bash
make                            # sin.sav, sinppu.ppu и sin.dsk
make sin.elf                    # с символами, для gdb
```

Нужен образ примера — на нём рядом с программой лежит `SINPPU.PPU`:

```bash
../../debugger/bin/ukncbtldebug --disk1 sin.dsk \
    --rom ../../rom/uknc_rom_autoboot.bin --boot --screen
```

и в RT-11 — `RUN SIN`.

## Что в нём смотреть

**libm на этой цели.** Плавающие здесь в формате DEC, а не IEEE, а
математические функции newlib — это fdlibm, который читает порядок и мантиссу
прямо из битов, считая их уложенными по IEEE. Пока форк gcc не научил эти
чтения форматам DEC, `sqrt(4.0)` и всё рядом возвращали бессмыслицу, и
никакой синусоиды тут быть не могло (см. раздел про libm в README проекта).

**Одинарная точность — не вкус, а размер.** `sin()` тянет за собой половину
библиотеки для двойной точности, и программа с такой графикой выходит около
50 КБ — RT-11 её не загрузит вовсе; с `sinf()` — около 35 КБ.

**Таблица на один период.** Один `sinf()` занимает заметную долю кадра, так
что 320 вызовов на кадр не оставили бы времени ни на что другое: значения
считаются один раз, а волна движется сдвигом по готовой таблице.

**Пиксели пишутся прямо в консольную память экрана** (смещение плана 0100000)
через оконные регистры 0176640/0176642 — запись адреса и запись данных на
каждые восемь пикселей. Не потому, что так лучше, а потому, что буфер в куче,
как в `gfour`, занимает 23 КБ, и 23 КБ поверх 35 КБ самой программы в 64 КБ
адресного пространства не укладываются. Текст, который был на экране, при
этом затирается, а на выходе экран очищается.

ПП-часть — исходник `gfour` без изменений, собранный под именем, которое
примет RT-11 (`SINPPU.PPU`): ей всё равно, на какое смещение плана указывать.
Палитра, тег-лист и клавиатура — оттуда же, см. `../gfour/README.md`.
