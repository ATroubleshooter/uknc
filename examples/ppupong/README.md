# ppupong — обмен данными с ПП в обе стороны

Десять кругов «ping N» / «pong N» между ЦПУ и ПП, по обоим каналам передачи
данных `libppu` сразу, и оба — на прерываниях с обеих сторон. ЦПУ-часть
(`ppupong.c`) загружает и запускает ПП-часть (`ppupongppu.c`), затем посылает
пинг, принимает понг, увеличивает число и так далее; после десятого круга
посылает сообщение «выход», по которому ПП-часть возвращает управление своему
резидентному монитору.

## Сборка и запуск

```bash
make                            # ping.sav, pong.ppu и ppupong.dsk
make ping.elf                   # с символами, для gdb (и pong.ppu.elf рядом)
```

Нужен образ примера — на нём рядом с программой лежит `PONG.PPU`:

```bash
../../debugger/bin/ukncbtldebug --disk1 ppupong.dsk \
    --rom ../../rom/uknc_rom_autoboot.bin --boot --screen
```

и в RT-11 — `RUN PING`. Имена на диске `PING.SAV`/`PONG.PPU`, а не
`ppupong.sav`/`ppupongppu.ppu`: в RT-11 имя — шесть символов и три.

## Что в нём смотреть

- Канал ЦПУ → ПП: `ppuc_send()` на этой стороне, `ppus_recv_init(callback)` —
  на той. Канал ПП → ЦПУ: `ppus_send()` там, `ppuc_recv_init(callback)` здесь.
  Порядок важен: если ПП-программа использует `ppus_recv_init()`, то на ЦПУ
  первым должен быть вызван `ppuc_send()`, и только после него
  `ppuc_recv_init()`, — иначе служебный байт подтверждения спутается с началом
  настоящего сообщения.
- Первый байт каждого сообщения — его тип (`MSG_TYPE_DATA`/`MSG_TYPE_EXIT`):
  сама библиотека смысла байтов в буфере не разбирает, и различать обычный
  пинг от команды на выход — дело программы. `MSG_TYPE_EXIT` здесь не
  формальность: без него ПП-часть ждала бы одиннадцатого сообщения, никогда не
  вернулась бы из `ppu_main()` и резидентный монитор не получил бы обратно
  свой приёмник канала 2 — от которого зависит консольный ввод-вывод RT-11.
- Парные `ppus_recv_shutdown()`/`ppuc_recv_shutdown()` перед выходом: вектор
  прерывания, оставленный указывать на освобождённую память, вешает монитор ПП
  на первом же следующем прерывании, а на стороне ЦПУ — на следующей
  загруженной программе, так как RT-11 память между программами не чистит.
- Пока идёт обмен, консольного вывода нет: он снова заработает, только когда
  ПП-часть отдаст управление своему монитору. Поэтому обмен проверяется по
  финальному сообщению, а числа форматируются своими
  `build_ping()`/`parse_num()` — `printf` рядом с файловыми операциями
  загрузчика на этом тулчейне пока нельзя.
